# Source-only ownership audit optimization design

Frozen baseline: ../queue-finite-owned-sol-v1; sources.json pins inspected sources. No queue or model execution was performed for this design.

## First implementation: no cache
Replace only ownership_intents pairwise overlap detection with component-aware ancestor membership. _validate(spec, False) already requires canonical absolute resolved output paths; preserve that validation before comparison. Use pathlib Path components, exact duplicates rejected, every strict ancestor including / included; input order must not affect detection. Never use string prefixes or adjacent lexicographic comparisons (/a, /a-b, /a/b is a counterexample). Do not resolve paths inside the comparator: filesystem alias/symlink/normalization semantics remain owned by existing validation. Generic comparator can preserve lexical Path behavior even for relative test cases. Root / overlaps every absolute descendant. This phase leaves all live reads, hashes, error messages, lock acquisition, ownership source pins, claims and scientific receipt checks unchanged. It does NOT solve repeated history-wide rehashes, potentially quadratic aggregate tick rehash cost, or durable queue scaling.

## Optional future same-operation structural reuse (NOT implemented/admitted)
A capability must be local to one continuously held exact managed dispatcher flock/open-file description, root/domain/source roster and process. Standalone execution gets no cache. Keep bounded ownership-lock acquisition on every call; never retain it across prepare or child waits. Freshly compute the full expected mapping digest on every use. Cache decoded structural reasoning only, never live input drift, terminal/process/session/output/recovery inspection or dependency qualification.

Fresh guard must enumerate all intent/attempt/output/job-claim namespaces and compare current bytes/pins, optional prepared/specification presence, and actual job-lock device/inode. Matching mtimes/sizes are insufficient. Re-run validate(spec) for EVERY historical intent on EVERY invocation: external input/executable bytes can change while dispatcher/ownership locks remain held. Return copies of evidence, never mutable cached objects. Unknown topology is a full-audit miss. Retain uncached final audit initially.

Invalidate before prepare and in finally even on partial-write failure; admissions/binding/reservation/ack/dispatch/launch intent change expected/required state; source/domain/store changes, lock release, error, repair, process restart and status-to-tick/finalize boundary invalidate. No persistent cache. Crash restarts begin with full audit. Even this design remains O(history) reads/hashes/live validation per invocation and is not an O(1) idle frontier.

## Adversarial differential plan
Use separately fresh source-bound baseline/candidate stores and real tiny executable fixture jobs, no inserted fabricated historical successes. Compare semantic outcomes plus independently validated evidence, not root/PID/timestamp-specific bytes. Inject deterministic seams between successive audits: mutate external input/executable; unrelated historical drift; edit/delete intent/spec/prepared/claim; introduce unknown entry; replace empty job-lock inode; mutate then restore mtime/size; change required flag/binding/reservation; source drift; caller-mutated returned evidence; held O lock; D release/reacquire; partial prepare crashes at every existing seam; supervisor completion/output/terminal corruption between calls. Cache must never hide these. Test fresh process crash replay and cooperating D contention. First no-cache phase uses exhaustive permutations/property comparisons against unchanged pairwise oracle, roots, duplicates, lexical normalization, symlinks/canonical rejection and original regression suite. Future bounded scale tests must use actual tiny completed jobs and report operation counts; none run here.

## Trust and limits
Cooperating trusted-local filesystem/processes; arbitrary coherent same-user rewrites, hostile filesystem races and power-loss guarantees are not solved. D excludes cooperating manager writers, not input edits. Existing source pins prevent adopting old stores under changed sources. No promotion, scientific qualification, unattended-service or thousands-cycle claim. Independent review required before deployment.
