# Independent review of the frozen frontier lifecycle derivative

The lifecycle derivative addresses the two predecessor gaps: transitive descendants of failed producers no longer remain indefinitely unresolved, and current-admission lifecycle snapshots have explicit states/counters. I verified the frozen source pins and replayed all eight tiny invented tests in a fresh temporary copy (8 passed, 4.801 s). The suite covers closure/commit crash boundaries, first-cause deduplication, concurrent admission/ticks, unknown exit, corrupt counters, completion reopening, and version/source rejection. No actual model/owner work ran.

The transactional design is coherent under the stated trusted mutable SQLite/cooperating-writer model: release row, terminal blocks, pending removals, active deletion and counters share one DB transaction. Recursive `UNION` deduplicates diamond paths. A failure before commit leaves the attempt active; a commit preserves the full terminal closure. First cause remains immutable if later failed roots reach the same blocked work. No runnable descendants escape this transition in the tested DAG fixtures.

One API caveat: an empty store returns `state='empty'`, `total=0`, `all_terminal=true`, and `all_executions_accepted_unqualified=false`. This is mathematically correct for the declared “all currently admitted owners are terminal” predicate and documented as vacuous terminal status. It is dangerous if a consumer treats `all_terminal` alone as a queue-completion or success flag. Consumers need the status/total and success qualifier; a future API could rename the boolean to `all_current_admissions_terminal` or set it false for an empty store.

Durability remains process-crash evidence, not power-loss evidence. The inherited connection uses rollback-journal mode and synchronous FULL. SQLite's own documentation says FULL in rollback mode might not be power-loss durable across all filesystems; EXTRA adds a directory sync after rollback-journal unlink. A transaction still cannot include arbitrary JSON files, so file/DB recovery needs exact replay and authenticated state classification. The frozen design correctly leaves this as a documented limitation.

The full descendant closure runs in one transaction. This gives simple atomicity but can hold the cooperating dispatcher lock and grow in CPU/memory/journal size with a large graph. No large-DAG/throughput or power-cut test is present. If closure fails, retaining the active reservation is safe but can leave the queue unresolved. Counts and current completion are mutable operational projections; only the explicit O(history+graph) audit reconstructs them under the trusted-store assumption.

Detailed source pins and replay outputs are in `review.json` and `evidence.json`.
