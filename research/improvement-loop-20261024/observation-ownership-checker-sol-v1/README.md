# Reusable observation-ownership claim checker V1

This is a strict, executable INTERNAL CLAIM-CONSISTENCY gate, not authenticated evidence resolution. It takes a caller-supplied manifest plus a separately retained expected manifestSHA and returns aggregate counts/status only. It does not open source artifacts, derive raw field meanings, authenticate release/vintage, validate factor code/math, prove target-roster completeness, or authorize a fit. Every result states source_admission_authenticated=false, joint_law_authenticated=false, model_vector_binding_authenticated=false, sampling_attestations_authenticated=false, verified_independence=false, scientifically_qualified=false. A coherent fabricated manifest can pass internal consistency; a specific boundary test demonstrates this. This limited scope is intentional and must survive integration.

## Typed evidence and interfaces

Use audit(manifest, expected_manifest_sha256) from checker.py. test_checker.py provides complete invented schema fixtures. Top-level model binding pins name the selected problem/composition/complete target roster; every factor pins its implementation and exact ordered components/observation metadata vector. Manifest/vector hashes detect changes relative to retained pins; they are NOT independent provenance because a caller can coherently reauthor all hashes.

A declared original observation atom is(source origin namespace, source-scoped record token, stable raw field ID). Stable measurementID, rawunit, event and measurement period must agree wherever that atom reappears. Event identity is temporal/target context, not duplicate identity. A person's two different question fields are distinct observations with unresolved dependence; two source records sharing an event are not automatically duplicates. Target/modelunit/transformation pin remain separate from original atom, so relabeling a target or transforming the same field does not evade duplicate detection. Unit changes require a transformation pin; implementation semantics are not verified.

Same original atom in two independently multiplied likelihood factors reports duplicate_declared_observed_atoms even across source aliases or declared derived-statistic lineage. Repeating it in one component rejects. Components inside ONE declared joint factor may reference the same original atom only with a joint-model pin; output calls this joint_internal_atom_reuses and never authenticates that the mathematical law is a valid normalized joint. Do not represent p(y)×p(y) as one declared joint factor to bypass review. Multiple factors cannot excuse duplication merely by claiming pairwise joint dependence; one coherent group/vector law must be reviewed externally.

Each source pins bytes, origin lineage/provenance, availability and typed role. Identical byte hashes with conflicting namespaces reject; declared derived source versions sharing an origin namespace resolve to the same atom. Unknown/different namespaces for genuinely identical physical evidence remain an unresolved alias problem, not something generic syntax can authenticate. Field/measurement semantics and derived-statistic origins need an actual source-reading resolver/lineage audit before applying this to scientific evidence. Sources are typed observed/derived_observed/deterministic_input/uncertain_input. Shared covariates can be reused without being counted as observed atoms; observed-derived inputs entering priors/shared inputs trigger evidence_input_review_required (including coordinate metadata, conservatively requiring review). Reused uncertain-input references flag shared_uncertainty_review_required rather than pretending independent duplicated uncertainty is harmless. This is not a complete uncertainty-ownership proof or an actual graph prior/coordinate audit.

## Distinct observations are not independent samples

Disjoint declared atom sets are counted explicitly, distinct from respondent/sample overlap. Default overlap isUNKNOWN, not disjoint because source names/record IDs/dates differ. Optional DeclaredSamplingPartitionV1 metadata must name a common namespace/unit/provenancepin and exact opaque membership labels; pairwise label sets yield declared disjoint or known overlap only under that supplied attestation. This is still UNAUTHENTICATED metadata, not a verified design/people-disjointness proof. Shared source/error dependence is kept unknown for every cross-factor pair, even with disjoint declared samples. No verified-independence result is possible. All multi-likelihood compositions therefore retain overlap_review_required unless a higher-priority duplicate/input warning applies; a single factor can be structurally_consistent_claims only, never scientifically qualified.

Dates distinguish source available_at, observation period and manifest cutoff, with event identity separate. Every claimed source/period must end by the declared cutoff. Timestamp checks do not prove original publication or train/forecast role. Target-roster/model/vector pins are shaped commitments, not content verification. Unknown source timing/measurement scope should not be invented to make the schema pass; this gate is not usable for an incomplete actual ledger without an explicit separate missing-evidence decision.

## Frozen A2018 aggregate check

Use audit_a2018_aggregate(path, expected_sha256) with independently frozen V2 aggregate bytes. It verifies only source-pinned aggregate consistency:66factor blocks,8242memberships(65survey/7968memberships,1poll/274rows),Arizona20poll rows/no direct survey/count/report, original8×.125 masses and unqualified status. It explicitly returns record_ownership_audited=false and sampling_overlap=unknown. It does not reconstruct real survey atoms or infer unique persons; no row-level source tokens are serialized, copied into this packet or printed. Source pins reference the frozen source ledger/critique rather than duplicating it.

## Tests, limits and next adapter

Eighteen invented tests pass in fresh temporary scratch. Cases include exact duplicate atoms, two questions from one record, joint internal representation, target/transform/source aliases, declared derivations, conflicting measurement/unit/event/time, source lineage conflicts, disjoint observations with unknown dependence, false disjoint-sampling assertions remaining unauthenticated, common covariates/uncertainty, observed input in coordinate prior, vector/retained pin tamper, late source/period, empty composition, output-token suppression and literal-pinned aggregate consistency. No model/data arrays/jobs, owner edits, ranking, release or forecast qualification.

Run nice -n15 python3 -B -m unittest test_checker -v in a fresh local copy of checker.py/test_checker.py; actual aggregate is read locally by its pinned path and no row output is retained. The code has O(F²) pair review/set intersection plus manifest/claim hashing, no production-size or thousands-cycle benchmark and no hostile-filesystem/data admission guarantee. Inputs are caller-owned in-memory mappings; keep them stable during the call.

The next concrete scientific adapter must read exact source bytes locally, derive original field/measurement lineage and trusted transformations; preserve respondent/sample/error unknowns; bind the complete selected Problem, roster, source/vintage, ordered vector/covariance and true factor graph to externally reviewed hashes; then feed resolved claims to this gate. No generic caller-picked atom/provenance/hash can substitute for that adapter. The current A2018 source-level ledger and its independent closure review provide stronger source-specific evidence than this generic claim gate. Their original-G conditional-prior/shared-kappa/Jacobian limits remain intact.
