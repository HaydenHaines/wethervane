# Finite-owned queue scaling assessment V1 — source only

Frozen source analysis and **unexecuted benchmark design**. No queue/executor import, subprocess fixture, store, scientific/model job or workload benchmark was run. No frozen file was modified. `analyze.py` reads/hashes/parses source and does arithmetic; four tiny arithmetic tests pass. All 29 local pins declared by the frozen predecessor evidence currently match, including the cleanup evidence restored by root after independent testing.

## What scales

Let **P** be admitted plans, **J** queue-job records, **R** job records with reservations (including released), **A** distinct retained executor attempt intents, **E** dependency edges, **H** independent retained roots and **B** bytes whose pins must be read. These are not interchangeable. Prelaunch resumption can give multiple queue records for one attempt; failures/retries add attempts; blocked descendants can have results without reservations.

`cycle_id` is identity metadata, not evidence of a scientific improvement cycle. A real cycle additionally needs authorized candidate/model runs, joint scoring, diagnostics, qualification, selection and conflict-safe promotion evidence outside this dispatcher. Seventy-three fixture tests are not 73 cycles. Each store is one finite OPEN→SEALED→FINALIZED generation; it cannot reopen. Thousands of adaptive admissions could occur while OPEN, but thousands of separately finalized generations require separate roots and an external coordinator. Capacity/ownership is per root: neither root rotation nor distinct cycle labels supplies global scheduling, promotion coordination or cross-root output exclusion.

## Dominant source-derived costs

Source aliases Q/E/F refer to the frozen packet's experiment_queue.py/execution.py/finite_intake.py; exact hashes/function lines are in source-analysis.json.

| Path | Actual work and implication |
|---|---|
| Idle tick, Q:463–566 | Reconciles every released reservation with verified_result, then `_status_snapshot` verifies every job again. Each reserved result invokes `ownership_for_job`, which rebuilds all expected bindings and calls full ownership audit (Q:595–625). Healthy completed history therefore performs **2R full ownership audits per idle tick**. |
| One ownership audit, E:907–938 | Scans all intents/claims, compares each pair of A output paths (E:377–379), reconstructs evidence, checks job/output claims and freshly validates every historical executable/input to report drift. Cost includes A(A−1)/2 containment checks, metadata reads and live byte hashing. Q's expected-roster rebuild adds full plan/reservation reads each time. |
| Healthy all-success N=J=R=A | **N²(N−1) containment comparisons and 2N² executable rehashes per idle tick**, before other pins/metadata. At N=1,000 the arithmetic projection is 999,000,000 comparisons, not measured executions. The observed local interpreter file is 8,020,928 bytes (stat only); if every spec uses that executable, those rehashes imply 16,041,856,000,000 logical bytes read in that tick. Warm page cache can avoid physical disk reads; it does not remove current hashing. This is not a wall-time prediction or disk-traffic measurement. |
| Status/finalization | Status still does R audits; it is not a cheap progress endpoint. Finalize calls tick plus one explicit audit, then constructs/pins/serializes full evidence. Healthy all-success counts are N audits for status and 2N+1 for finalize. |
| Admission, Q:206–268 and F:80–103 | Frontier rereads all accepted plans/admission pins/scaffolds; enqueue performs original preflight twice and scans old references for each new job. k new jobs imply at least history×k conflict work plus within-plan k² containment checks and live spec validation. A stream of singleton plans accumulates quadratic admission history work even before ticks. |
| Managed gate, E:856–900 | Both prepare and launch scan ACCEPTED DB/plans/receipts/scaffolds and reservations. The directory test rebuilds `{r[0] for r in rows}` for each directory, adding P² identifier work. Many singleton plans and one large plan must be measured separately. |
| Dependencies | Producer verification/binding invokes more full ownership audits. Plan scans and producer lookup add E-dependent cost; dense/fanout DAGs are not represented by an independent-job test. |
| Live processes/locks | Capacity is 1 or 2 attempts, not one or two OS processes. Supervisor/child/manager and `/proc` observations add process-dependent costs. D serializes queue operations, O serializes ownership changes. Per-acquisition .5 s lock/busy timeouts do not bound a full tick, repeated audits, scheduler delay or I/O calls. Slow full audit while D is held makes admission/seal/other callers contend even when no model runs. |
| Memory/disk | `pin` streams 1 MiB blocks, so a large pinned artifact need not be fully resident; hashing time still scales with bytes. JSON plans/intents/expected maps and final canonical JSON are materialized, with duplicated spec/evidence representations. SQLite FULL commits and per-record file/directory fsync add durability latency. Retained logs, results, claims, outputs, final DB blob/projection and inode counts grow; no safe GC/archive-compaction API exists. |

The cubic term is a particularly bad repeated full-history composition, not proof every operation is cubic or that CPU comparisons always dominate elapsed time. For tiny N, interpreter/input rehashing, process startup, source pins and fsync may dominate. Actual call/byte/syscall timing needs measurement. `source-analysis.json` contains projections under explicit healthy-released assumptions; no timings were extrapolated.

## Representative measurable pilot

`benchmark-plan.json` is a plan, not a runner or result. First build a source-bound external harness in a new packet. Primary measurements must invoke the **unmodified frozen dispatcher/executor** on fresh temporary stores with every reconciliation, source, reservation, dependency and ownership check enabled. No mocked terminals, fabricated historic stores, copied/moved stores or disabled hashing/flushes. Root/source paths are bound, so an archive copy cannot bootstrap an authenticated history at another path.

Start with capacity one and adaptive singleton admissions at completed-job prefixes **1, 2, 4, 8**, using real bounded no-fork tiny Python commands and 1 KiB fixture data. Record actual P/J/R/A/E, accepted result and terminal rosters, and no-live-reservation evidence at each prefix. Measure separately: initialization; enqueue; one dispatch tick; active polling count and time; completion/release; three **fully completed idle ticks**; status; cold-controller restart on the same exact root; seal; first finalize and exact finalization retry. OPEN completion is idle, not final. Do not compare a full-history completed idle tick with a cheaper early-return/pending/corrupt path.

Subsequent separate bounded batches compare: one big plan vs singleton plans at equal J/A; small within-plan producer→consumer chains; explicit terminal retry and restored-input prelaunch resumption; capacity-one live/unknown reservation; and H=0 vs H=2 retained finalized roots at the same active-root size. Construct archived histories through real calls in place and retain all files. An active root does not normally scan sibling historical roots; catalog/revalidation time and aggregate retained disk must be reported separately. Root sharding may limit per-root cost but is not a verified thousands-cycle controller and changes ownership/capacity scope.

The first batch caps **16 actual launches total**, one live attempt, nice15 and a proposed 120 s batch budget. Proposed stop thresholds: 5 s per operation, 128 MiB allocated scratch bytes, 10,000 filesystem entries and 256 MiB observed controller RSS. These are operational stop criteria, not Linux real-time or whole-process-tree memory guarantees. Stop and preserve partial/failure evidence when limits are reached. Do not silently omit slow/error samples. Tiers 16/32/64 are separate later work only if prior measurements and fresh resource checks fit budget; no automatic 1,000-job workload.

Measure wall time and direct controller CPU/RSS with their scope; record owned process identities/counts, data sizes, file/inode/allocated-byte growth, tmp journal/temp-file leftovers and exact durable controller returns. Distinguish logical hash/read bytes from actual storage reads and OS warm-cache effects. Do not drop global caches or perturb active owner jobs. Use external observations for primary timings. Optional wrapper/call counters belong to a separately labeled diagnostic run with harness code pinned and outputs/status compared; wrapping a function at runtime is not an unmodified-source timing trial. No counter may skip original work, and counters alone are not throughput evidence.

Fresh-source/resource check and independent technical review precede execution under standing authorization, not a new user-approval gate. All outputs/cleanup reports must go to caller-selected scratch, with frozen source pins checked before/after. Fixtures must have finite no-fork behavior and tight executor timeout/grace. Hard watchdog/launch-crash tests need authenticated child birth/cleanup proof or a separately verified delegated containment boundary; never kill an unproven PID/session or assume killing the caller kills detached workers. Abort further trials if cleanup cannot prove no fixture remains; preserve unknown reservations. Early pilot faults should occur with no live job or after recorded identities, not invent coverage of an unrecorded startup gap.

Fault/corruption trials use independent fresh histories and one mutation per trial so sticky quarantine cannot mask later mutations. Preserve genuine enqueue/seal races, exact retry/duplicate rejection, interrupted preparation/ack replay, post-release mutation rejection and unchanged final projection. Throughput that loses any of these is not a scaling success. Larger fixtures do not authorize scientific jobs or justify model-cycle/forecast claims.

## Practical next implementation path

1. Implement only the external scratch-output pilot harness, verify the existing suite without overwriting frozen evidence, and measure the unmodified small baseline above. Establish which costs dominate and exact operation counts under actual P/J/R/A/E.
2. In a later source-bound successor, investigate a **transaction-scoped** authenticated audit context under D/O: one full current history audit per public operation, with explicit invalidation/update after every self-published claim. Fresh target/dependency/launch checks remain. Context must not survive a public operation or become a trusted stale persisted index. Original managed-gate S must finish before O; internal prepared-context methods must not reacquire O through another fd or introduce O→S/J→D waits. This is an unimplemented design requiring semantic/race review, not an asserted safe optimization. Preserve or explicitly version the visibility of external mid-operation mutation; repeated old checks cannot simply be deleted under a weaker hidden trust rule.
3. Separately replace all-pairs containment validation with a proven component trie or component-tuple sweep **rebuilt from authenticated current claims**. Native string sorted-adjacent checking is invalid (`owned`, `owned-other`, `owned/child`). Require exact/reversed/nested/sibling/duplicate/cross-plan/pending regressions and randomized comparison against the existing all-pairs predicate. Rebuilding a deterministic trie per audit does not inherently require trusting a mutable persistent index. It still leaves full-history reads/hashes.
4. Only after correctness differential tests and representative measurements, consider retention/index changes with an explicit trust contract. An append digest/Merkle root in the same owner-writable store does not prove mutable old files stayed unchanged without rereading or a stronger immutable witness. Periodic rather than per-operation verification is a semantic change, not free scaling. Fixed batches need authenticated predecessor/qualification/promotion handoff and global resource ownership before counting real multi-root cycles.

## Reproducibility defect and current evidence

The frozen `run_tests.sh` changes cwd into its source packet and `run_tests.py` writes `Path('cleanup-verification.json')` unconditionally. An independent rerun overwrote tracked cleanup evidence; root reports restoring it after Luna saved separate output. The current 29-pin check confirms restoration. This is a concrete reproducibility defect, not model evidence. Do not rerun that shell script in place. Future successors/harnesses must require an explicit output directory (or default fresh scratch), refuse overwriting evidence, and assert source-tree pins unchanged. A carefully controlled direct runner invocation from scratch can avoid that relative output, but needs its own tested import/cwd contract; this packet supplies no such harness.

Actual work here: source/hash/AST assertions, interpreter metadata stat and four arithmetic tests (0.000 s reported). No store, fixture job or performance benchmark ran. Source checks substantiate call structure; they are not dynamic counts, proof of liveness, a fitted performance model or a thousands-cycle result.
