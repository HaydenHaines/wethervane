## Real path, not yet exercised

After independent review and a fresh operational admission manifest, `python3 -B pilot.py --execute /caller/scratch/admission.json` selects the real path. There is no fake mode CLI. The template in this packet is intentionally expired and incomplete; copy/fill it outside this packet, including exact reviewed harness pins and the authoritative current owner guard snapshot. Standing authorization is retained; this is a source/resource boundary, not a new user-approval gate.

All writes go to a fresh mode-0700 UUID directory below a caller-selected canonical scratch parent, on the selected source filesystem and outside source/harness/protected-owner trees. Existing output is never reused. Receipts are exclusively created with file and parent-directory fsync; scratch creation also syncs its parent. Source and protected owner-state pins are checked repeatedly, and again by phase workers. `-B`/PYTHONDONTWRITEBYTECODE prevent source bytecode writes. No output path defaults to a frozen packet. Source guards retain the predecessor's cleanup evidence, addressing its tracked-file overwrite defect.

The real driver creates one fresh process per action, joins the **provided dedicated cgroup before source verification and queue import**, lowers priority to at least nice15 and calls the unmodified queue. Its inherited supervisors/children stay in that domain under the trusted fixture/executor behavior. Each worker has recorded PID/start-tick/boot identity, entry/result receipts and external return/stdout/stderr pins. Worker operation time and outer phase elapsed are both recorded; enqueue timing includes constructing/pinning the fixture specification. Python bootstrap before cgroup join and the outer monitor are outside the leaf counters and are not mislabeled as complete cgroup CPU cost.

The literal fixture is finite, no-fork, 1 KiB file work with fsynced native metadata. Queue capacity is one; executor timeout is 2 s with .05 s grace. Admissions are cumulative jobs 1…8 in **one unchanged history**, observed at 1/2/4/8. At each prefix the harness requires actual accepted terminal records, then measures three completed idle ticks and two fresh-process status calls. It measures initialization, enqueue, active polling/completion, seal, first/exact-repeat finalize and before/after control actions. Fresh process is never called cold cache. All queue ownership/reconciliation/dependency/source checks remain enabled.

There is a hardcoded ceiling of 16 observed execution launch intents, with admission checks before adding work; this first pilot normally has eight. There are no automatic larger tiers, scientific candidates, scoring or promotions. `cycle_id='invented-pilot-series'` is identity metadata, not eight scientific cycles. Results explicitly report scientific_cycles=0 and unassessed scientific qualification. Retention/fault/DAG/alternative-packing cohorts remain later work.

## Resource and owner admission/continuation

The harness consumes an explicitly selected **existing fresh empty delegated cgroup-v2 leaf**, not the root cgroup and not a user service containing sibling scopes. It does not create groups, change parent limits, enable controllers or reset counters. Required kernel interfaces must be readable, cgroup.procs/cgroup.kill writable, no child groups, zero initial CPU/peak-memory/event counters, finite quota ≤1 CPU, memory.max ≤256 MiB and pids.max ≤16. Missing I/O accounting or per-member visibility refuses admission rather than using incomplete controller-only measurements.

Default controls are conservative and fixed in code:

- Explicit protected owner roots, small authoritative state-file pins and protected PID birth identities are mandatory handoff fields. Any discovered active guard-scoped owner workload, identity reuse, source/state change or incomplete same-user discovery stops the batch. Known active owners are **not** admitted on a merely stable baseline. This exclusion is scoped to the caller's complete guard handoff; it does not prove every process on the machine is identified. Root/cmdline/cwd discovery supplements explicit identities. No owner is signaled or changed.
- Host CPU/load ≤50%, memory available ≥2 GiB and 20%; host/leaf PSI some avg10 limits CPU5%, memory.5%, I/O1%. Ancestor CPU usage minus observed leaf usage must leave the full requested leaf quota plus 25% ancestor capacity; finite ancestor memory must retain 576 MiB. Root-host CPU and affinity headroom are separately checked. Raw counters are retained, not silently rebased after resets.
- Leaf current memory must leave 64 MiB phase headroom; observed outer-monitor RSS ≤256 MiB; no memory-event or pid-limit event increments; observed leaf pids ≤8; throttled time increase ≤25% of observation interval. Kernel memory.current/peak are resource charges, not summed process RSS. Sampled RSS can double-count shared pages; PSS is recorded separately, and neither is claimed as an unsampled instantaneous tree PSS peak.
- Storage requires ≥2 GiB/20,000 available inodes; allocated scratch plus one MiB and 128 entries per remaining slot must stay within128 MiB/10,000. The scratch-only fsync probe must complete ≤50 ms. Host diskstats, cgroup io.stat and PSI are retained; the probe is an operational latency observation, not a device tail-latency or scientific storage benchmark.
- Two baseline observations precede the first worker. Before/during/after observations occur at approximately100 ms polling intervals. Owner starts/queue changes, resource pressure, missing/nonfinite inputs, counter resets, worker failure or uncertainty abort **further admission**; collected intervals stay in the receipt history, rather than being silently excluded. OS caches are neither dropped nor forced cold; Cached/Buffers and explicit uncontrolled-cache policy are recorded. Probe/monitor overhead can perturb timing; control actions expose some of it but do not justify subtracting it away as pure queue throughput.

Requested phase/batch wall stops are5 s/120 s. They are checked around monitoring/polling; blocking filesystem/proc reads, scheduling and uninterruptible kernel I/O cannot be preempted by these Python checks. These are operational stop criteria, not hard real-time guarantees. SQLite/flock timeout behavior remains that of the frozen queue. No production pressure or latency trace has been collected here.

## Detached accounting and cleanup

The dedicated leaf's cumulative cpu.stat, memory.current/peak/events, pids and io.stat account for queue workers and detached descendants that stay in that leaf. Per-member birth/CPU/RSS/PSS samples supplement those aggregate counters; a very short process may exit between samples and is recorded as such rather than receiving invented PSS. Kernel counters still cover its in-domain resource use. This design depends on the immutable-by-convention trusted fixture/executor not migrating out of the leaf; it is not anti-evasion or hostile same-user isolation. Cgroup inheritance/hierarchical limits are documented by the [Linux kernel](https://docs.kernel.org/admin-guide/cgroup-v2.html). Permission and process-memory observations have the [kernel /proc limitations](https://docs.kernel.org/filesystems/proc.html).

On abort, directly created phase processes are stopped only through retained PID birth identity and pidfd, including a possible pre-join worker. The leaf identity is rechecked. Remaining leaf members must have the pinned harness/executor/fixture command-family paths before group kill; an unproven member refuses group signaling. Cleanup then requires cgroup populated=0 and reaps direct children. Failed identity verification, unavailable cleanup or unresolved population yields cleanup_uncertain, never a completed pilot. Scratch and incomplete reservation evidence are retained; nothing guesses a scientific or successful process outcome from absence. No cleanup path intentionally signals an owner or unrelated group. This cleanup code has **not** been exercised against a real cgroup; fake tests verify orchestration decisions only.

Durable receipt creation itself can fail under storage failure; an external caller must preserve the tool/process failure return if no final receipt can be written. There is no disk-full, power-loss, adversarial group-migration or exhaustive launch-race proof. Full detached in-domain aggregate accounting is the required real-admission design, not an empirically validated achievement in this packet.

## Current environment is not admitted

`environment-readonly.json` records only stat/access/controller reads of `/sys/fs/cgroup/user.slice/user-1000.slice/user@1000.service`. It is hayden-owned and directory-writable, with cpu/memory/pids delegated, but it has three child groups, unlimited limits and no writable cgroup.kill at that node. More decisively, io.stat/io.max are absent and io is not an available delegated controller; io.pressure exists but does not replace attributable I/O counters.

No leaf was created or configured, no process was moved/killed, and no limit was written. This observation does not prove a usable child leaf or per-PID permissions. Under this observed subtree the strict full-I/O pilot is **not presently admitted**. A separately verified suitable delegated leaf and fresh source/owner/resource admission are prerequisites; this code does not request privileged controller changes or silently weaken its accounting.
