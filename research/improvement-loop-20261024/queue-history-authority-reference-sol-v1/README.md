# Capacity-one history authority REFERENCE

**trusted_mutable_same_uid_reference. Unadmitted; independent review pending.** This is a small standalone SQLite correctness reference, not protected storage, a production service, source/scientific admission or an existing-queue replacement. It launches NO executor/model workers. All test outcomes/cleanup records are explicitly invented. Original queue/code/owner jobs, parent weights and infrastructure remain unchanged.

## What is implemented

reference.py implements fresh version/source/root-bound domains, content-addressed invented admission-byte objects, canonical append events/hash-linked head, transactional idempotency responses and unique job/output/dependency ownership. SQLite DELETEjournal/FULLsync is requested; objects/events/claims/frontier/response are ONE database transaction, not an external-filesystem CAS durability demonstration. Head/domain/source/policy protection is not supplied by SQLite ownership or hashes.

Admission takes an exact head/lease and idempotency key, canonical job/target/unit/absolute logical output/dependencies, and at most64KiB invented bytes. API has64job/512event/32dependency caps. Output conflicts use canonical single-root POSIX path components (duplicate/ancestor either direction, including all permutations of /a,/a-b,/a/b); relative/dot/double-root aliases reject. These are LOGICAL claims, not verified physical filesystem paths: symlink/materialization/OS output ownership is not implemented. Dependencies must be existing unique earlier jobs, giving a DAG without future/migration claims.

Capacity-one reserve requires a ready job, no active slot, current head/lease and an invented worker token. Release requires exact active job/worker/reservationhash, exited status, cleanup_verified=true, well-shaped terminal/cleanup digests and accepted_unqualified orfailed; scientific qualification must befalse. Lease advance fences new requests but retains active capacity: expiry is NOT evidence of worker death. There is no worker launcher, OS observation, live launch token, resource scheduler, automatic retry or cleanup service.

IMPORTANT: structured cleanup evidence and digest fields are caller assertions. Coherently fabricated but internally matched cleanup is accepted in these invented tests and is NOT externally authenticated. Every status and historical receipt says runtime_worker_evidence_authenticated=false. The adapter for actual executor terminal/output/identity/cleanup bytes does not exist. Fake foreign/mismatched/unknown receipts reject; fake accepted projection/response edits reject, but that is not an OS-verification claim.

Each mutation begins IMMEDIATE, verifies canonical history/objects/source and derived projections, checks expected head as a prefix floor, then requires it to equal current head plus current lease for a NEW transition. Event/body/head/response and projection commit atomically. Idempotent exact-body retries are HISTORICAL LOOKUPS before fresh transition conditions; they return the original committed receipt even with the old head/lease when the old head is a valid prefix. Receipt has historical_commit_only=true and live_launch_authorization=false. It cannot be used as a new launch/release permission. Same key/different canonical body rejects. No old queue store can be imported.

## Frontier, finality and recovery

jobs/ready/active/projection_head tables are derived from canonical events. Reference replays ALL history and verifies referenced objects plus exact idempotency-response/projection equivalence on every normal operation. Corrupt projection blocks normal status/mutations; canonical_head/lookup can inspect verified canonical history without trusting it. Explicit rebuild requires matched head/lease, preserves authoritative history/head and atomically reconstructs projections. Replay/rebuild retries are idempotent. New active/dependency states come from event transitions, not a signed local cache or invented successful history from another queue.

Failure release recursively marks pending descendants blocked within the same commit; ready excludes failed/blocked/active and unresolved dependencies. No-ready/open isidle, notcomplete. Reports separately name nonempty_current_admissions_terminal, all_current_admissions_accepted_unqualified and closed_nonempty_batch_terminal. Failed/blocked terminal work is not successful/scientifically qualified. Empty domain cannot seal; closed batch refuses new admissions. Continuous multibatch/goal completion is outside this minimal finite domain.

Process death beforecommit rolls back object/event/frontier/response; aftercommit response loss resolves by exact idempotency lookup. Release uncertainty retains active until canonical replay resolves commit. Rebuild can be retried after pre/postcommit death. Bootstrap(create) has no automatic partial-initialization repair, and unknown/malformed state refuses rather than adopting guessed authority. These tests exercise process death, not kernel/power loss, diskfull or all fsync uncertainty.

## Rollback, split brain and nonce boundary

A caller may retain exact(domain,sequence,hash) floor outside this mutable store. Source replay verifies that prefix; lower history or same-domain/same-sequence different-hash fork rejects. Without that floor, a coherent restored/forked same-UID history can pass—as a test demonstrates. No local trigger/hashchain/chmod/nonce supplies real independent protection. The caller-held variable in tests is not a securely hosted monotonic service or durable restart/bootstrap policy. Arbitrary same-user coherent rewrites/forgeries remain outside guarantees.

head_response echoes nonce/domain/floor after local prefix verification. check_response rejects stale nonce/domain/floor claims but returns authenticated=false; there is no network transport/signature/key custody and a caller can forge a coherent response. New clients require trusted bootstrap and a real independent anchor before any stronger claim. Source pinning checks local implementation bytes/path against storeconfig, not current loaded code under an adversarial code/FS race. The reference is a contract oracle, not an authority security boundary.
