# Candidate earlier polling archive for the 2018 replay

FiveThirtyEight's pollster-ratings database is a **different candidate source** for an earlier-only calibration experiment. The pinned GitHub commit [`142cad5610ed6b3468e730199034b280b9e805d5`](https://github.com/fivethirtyeight/data/commit/142cad5610ed6b3468e730199034b280b9e805d5) records a committer date of 2018-05-30, before the 2018 Senate forecast cutoff. The publisher's [2018 article record](https://data.fivethirtyeight.com/) identifies a May 30, 2018 pollster-rating update; the article URL now redirects to an unrelated ABC page. A Git commit's timestamp alone is not an independent trusted timestamp that proves the exact bytes were publicly available then. This is evidence for a dated archive candidate, not a completed provenance admission.

Source: [`pollster-ratings/raw-polls.csv` at the pinned commit](https://raw.githubusercontent.com/fivethirtyeight/data/142cad5610ed6b3468e730199034b280b9e805d5/pollster-ratings/raw-polls.csv), by FiveThirtyEight, distributed by its repository under [CC BY 4.0](https://github.com/fivethirtyeight/data/blob/142cad5610ed6b3468e730199034b280b9e805d5/LICENSE). Original bytes are preserved unmodified as `raw-polls-20180530.csv`; the Git blob SHA-1 is `39675528c20d57e88fbb1147ee10f6295f7061da` and SHA-256 is `79489a9d7f796d8f50841e91d8dcb858679ada75690812d4757f095a107efb91`. API metadata and commit metadata are included. Attribution and license remain attached to any reuse.

`python3 research/improvement-loop-20261024/m01-538-archive-root-v1/audit.py` checks these source bytes and the existing 2018 training-file digest and reproduces `candidate-inventory.json`. The archive has 465 2012/2016 Senate general-election rows; all recorded poll dates lie 2–21 days before the associated election. Four 2016 Louisiana records concern the December runoff and require separate event and cutoff handling. It is a late-poll selection, not a representative full time series. The existing 2018 training file contains 930 records and has a materially different provenance and support.

There are 30 unique archive-key candidates whose state, cycle, recorded poll date, normalized exact pollster name, and Democratic two-party share within half a percentage point agree. The archive describes its poll date as the **median field date**, whereas the Tierney preparation labels its date as the **end date**; equality of those values does not establish that the polls match. This deliberately conservative automated screen is **not** an identity join: polling releases can share those fields, report different samples, change question wording, or undergo transformations and rounding. It also does not establish that the 2023 Tierney source bytes existed in 2018. Original poll releases, sample/question identities, candidate and source transformations, and overlap with target/evidence factors require review before any row-level admission. An initial Fox Arizona source check in the companion `m01-vintage-followup-luna-v1` packet found a plausible but mismatching poll and reinforces that caution.

Potential next experiment: construct an explicitly separate, earlier-source calibration arm and a fair incumbent arm trained on the same reviewed archive cohort and cutoffs, then jointly bind the complete forecast and compare using the existing matched validation plan. Establish source-availability evidence, the transformed candidate targets, the treatment of non-D/R races, true sample ownership, target and training support, and licensing before fitting. The file embeds election results and error statistics. Earlier election outcomes can be used as labels only where they were known before the target cutoff; no target-election outcomes or derived error fields may enter pre-election features or calibration. The 2018 archive cannot by itself supply 2018 or 2020 data to subsequent folds and does not fix the unverified vintages of other sources. No data is admitted, model fitted, score generated, incumbent promoted or public forecast changed by this inventory.
