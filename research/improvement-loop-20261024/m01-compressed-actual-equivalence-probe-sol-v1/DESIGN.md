Failure/publication/trust boundaries

Any exception or KeyboardInterrupt after Popen enters finally: terminate only the owned process group, escalate after5 seconds and reap; write terminal PID/exit/reason/peaks. Failure to publish terminal is itself failure, never completion. Tiny tests inject a launch-receipt exception and controller interruption against real sleeping children and verify reaping and terminal evidence. SIGKILL/power loss/controller crash before cleanup cannot be guaranteed handled by Python finally; no claim of protection against those events. No partial pickle is loaded or touched.

Atomic JSON writes include file and directory fsync, but fsync exceptions after rename can leave visible uncertain markers. Success requires clean controller exit and its returned caller-retained acknowledgment; discovering/re-hashing an apparent marker is not authorization. The compressed controller prints its completion acknowledgment only after numerical comparison succeeds. Local hashes/locks are trusted provenance and concurrency tools; they do not defend against arbitrary hostile coherent rewrites, mutation after verification, unexpected external filesystem semantics or power loss. NPZ numerical outputs are fixed computational data, not authorization to deserialize executable objects. Source bytes are rechecked at each arm start/end, but immutable filesystem guarantees are not claimed.

Evidence from a successful future run would concern two supplied states, one protected parent and computational equivalence only. It would not establish separately normalized downstream conditionals, all-parent correctness, empirical predictive skill, historical replay, posterior diagnostics or a 2026 forecast. A scientific comparison remains subject to refine-model-layer and verify-election-model historical A/B evaluation; no numerical probe substitutes for that.
