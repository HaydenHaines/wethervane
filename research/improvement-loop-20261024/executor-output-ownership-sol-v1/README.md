# Direct-executor output ownership research V1

Frozen for independent review, **not production adoption or broad isolation**. New packet only; finite-run V1/V2 and original queues/stores remain untouched. No scientific jobs, graph builds or fits. This successor protects component-aware output claims among cooperating clients of this exact source in **one dedicated execution root**. It does not sandbox child writes, coordinate distinct roots, or force legacy/noncooperating same-user managers to honor its lock. All managers in this domain must use the successor. No migration/adoption of old roots is implemented.

## Actual mechanism

`prepare()` validates the exact current source/dependency paths and specification before writes. The store binds its canonical root and exact execution.py/ledger.py/run_receipts.py pins. Existing roots without this store marker are refused without adding files (except a new empty root or interrupted initialization containing only the ownership lock). A source mismatch, alternate dispatcher path or preloaded foreign dependency fails closed. Every `load()` additionally verifies the current store, new preparation schema, exact executing source and the preparation's ownership-intent pin/content. Thus inspect/launch/recovery using this successor cannot silently accept old preparations. Legacy code is not retroactively constrained by these checks.

`ownership.lock` is an execution-root-wide flock. It serializes **all successor prepare clients across different job keys**, fixing the gap in per-job locking. Under that lock, immutable-by-convention JSON ownership intents are scanned and every pair of declared output paths is checked with component-aware `Path.is_relative_to` in both directions. Canonical-path validation comes from the unchanged original validator. `/owned` and `/owned/child` collide; `/owned-other` is a distinct sibling. Equality collides too. There is no sorted-adjacent shortcut. Known attempts, exact output claims and job claims are checked against the intent namespace; observed orphaned or inconsistent claims block new preparation.

The original nonblocking per-job flock is acquired inside the ownership lock, preserving its process/session execution role. Lock ordering is global ownership → nonblocking job lock; original launch/recover do not wait for the global lock. A complete exact prepare replay can return its authenticated preparation while the worker retains the job lock. It does not relaunch the attempt. All preparation locks are closed before actual execution; the existing inherited flock remains held by supervisor/child as before.

A source-bound canonical intent is exclusively published and fsynced **before** creating an attempt directory/specification/prepared/output/job claim. It owns both output subtree and cycle/job identity across process death. A pending same-job intent must be exactly repaired before another attempt is allowed. Exact intent replay repairs each publication step, requiring exact existing record content and the original job-lock inode. The final job claim is published only after specification, prepared receipt and exact output claim. Launch registration refuses missing claims. Preparation retries never overwrite differing artifacts or adopt an already launched partial scaffold. A pre-existing unexpected output directory blocks repair.

Original explicit retry checks remain: new attempt and fresh nonoverlapping output, current retained job leaf, exact predecessor terminal/recovery receipt, matching cycle/job and absence of live process/session observations. Output claims remain retained after terminal states; no release/reuse or automatic retry is introduced. A successor attempt cannot branch from a stale predecessor.

Only `prepare`, `load` and `registered` changed among original functions. AST comparison in `ast-comparison.json` records 34 unchanged original functions, including launch, inspect, supervisor, child, terminal validation, collect, recover and stop. Their calls now reach strengthened load/registration. This source comparison is not a universal behavioral proof.

## Bounded evidence

Run `nice -n 15 python3 -B -m unittest test_ownership -v`. Frozen `tests-frozen.log`: **12 tests passed in 3.117 seconds**. Tests use real tiny Python subprocesses and temporary roots:

- Both ancestor orientations, exact collision and allowed lexical sibling; three genuine two-client conflicting races, simultaneous identical replay and simultaneous nonoverlapping sibling preparation.
- Real child exit at intent publication and five later scaffold boundaries, exact repair, retained conflicting claims and no launch during repair; a pre-intent exit can retry cleanly.
- Pending intent reserves job identity; changed duplicate specifications fail; real nonzero predecessor, successful explicit retry and stale-branch rejection.
- Actual live worker retains nested output claim, exact preparation replay remains idempotent; killed supervisor cannot be recovered while its child remains live, and original stop/recovery yields an explicitly unknown exit after cleanup.
- Partial receipt corruption, missing store, deleted intent with surviving prepared artifacts, stale source binding, alternate source and mixed import fail closed. Old/unadopted root and incompatible-source checks verify no new writes in the tested cases.
- **Negative boundary:** after a caller dies immediately after its sole intent is published, external deletion of that sole intent allows a nested claim when no attempt/output/job claim survives to witness it. The test deliberately records this accepted mutation, not a security success.

Cleanup terminates only fixture identities via authenticated pidfds, waits for no observed live fixture identity, and reaps exited directly owned supervisor handles where available. `cleanup-scan.json` separately found no matching fixture/executor arguments after testing; this is a narrow process snapshot, not an OS-wide lifetime proof. Temporary directories were removed. Peak temporary disk, CPU and RSS were not measured. No scale benchmark or thousands-cycle claim is made.

Earlier logs are preserved. `tests-failed-exception-class.log` has one test error: a missing intent correctly raised the executor's ValueError instead of the test's expected OSError. Only the expectation was corrected. Other interim passing logs precede final source hardening and should not be substituted for the frozen result.

## Explicit unresolved boundaries

Exclusive publication, file fsync and directory fsync provide the original cooperating local-filesystem process-crash contract. Files remain owner-writable, not WORM. An accidental or malicious unlink is an external mutation distinct from a killed caller; deletion of the sole intent without redundant evidence is the tested gap above. Coherent owner rewrites/rollback, legacy managers, noncooperating writers and lock-file replacement can bypass this trust model. No independently authenticated append-only witness, permission separation or hostile-owner prevention is supplied. Symlink/namespace changes after validation are not made safe by lexical containment checks.

There is no crash during fsync/publish internal system calls matrix, real power-loss/disk-full/NFS proof, exhaustive process schedule, complete original executor regression suite or queue adapter integration. A partial publish can leave an unexpected temporary file: the ownership namespace fails closed pending investigation rather than guessing repair. All-pairs scans are quadratic in retained intents and specification/input verification is history-wide; this is not the incremental scaling solution. Claims cannot be cancelled or garbage collected safely by this packet. Before use, independently review the narrower contract and test any intended queue adapter in a new source-bound store. Do not replace frozen V2 sources or reinterpret existing receipts.
