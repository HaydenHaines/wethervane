Existing evidence and the missing FD witness

The frozen V3 owned evaluator completed the dynamic all-eight three-point calls plus A return, and an independently built fixed-B ordinal1 comparison. Independent dynamic/fixed-B audits authenticated source, external caller-return acknowledgment, clean reaping, complete numerical receipts and the pointwise comparison. These establish neither parent normalizers nor posterior inference. The old dynamic finite-difference calls exist ONLY for B/ordinal1, not2–7. It would be false to compare fixed2–7 derivatives to those B values or infer derivatives from three unrelated base points.

Therefore this version has two explicit serial phases for each independently selected remaining ordinal:

1. dynamic-witness: build the same source-bound first-parent graph, replace the exact exposure input as before, compile once and evaluate ONLY the selected whole parent at the three existing exact points plus the two original variables' negative/positive h calls. Compare all three base outputs to that parent's already saved dynamic outputs, then retain new exact parent-bound FD witnesses. This phase does not create an independently fixed native target.
2. fixed-selected: independently build the unmodified native compressed-provider graph using that exact selected complete parent, compile logp/all factors/all contest rates/physical values, and compare three base calls plus exact FD settings against the selected witness. It requires the caller-retained successful witness acknowledgment for this parent. Fixed target identity must independently match the complete parent and native formula.

Each phase needs its own independent reviewed source/phase/allowed-parent selection and genuinely fresh per-job capacity assessment. No actual gate is selected by this packet. There is no batch mode, concurrent selected parents, model sampling, implicit promotion or partial-parent success aggregation. Running all six in this conservative implementation entails six dynamic and six fixed compilations if separately authorized; no such execution occurred here.

A future optimization could compile one separately reviewed dynamic witness once and evaluate all six parents' exact FD inputs serially. That would save repeated JIT cost, but needs an explicitly selected six-parent roster, immutable per-parent calls, a realistic whole-stage wall/disk budget, known cleanup/terminal behavior and no full-stage success from a truncated subset. It is documented rather than implemented late in this version. Individual fixed-native parent checks would still remain separate. Current resource/code gates are not relaxed for that proposal.

Acknowledgments, crashes and replay

Successful witness must be externally acknowledged before fixed-selected can run. Controller success is published only after clean worker reaping and verified comparison; caller must retain the successful tool return and its exact controller-success digest. Partial result files, a visible marker after failed fsync or a discovered/rehashed digest are not completion provenance. All prior caller acknowledgment requirements remain.

A crash before/during claim or any child/controller/comparison failure leaves files visible for investigation and refuses automatic execution retry. This version does not repair or resume partial graphs. An explicit completed replay needs the caller-retained acknowledgment and matches parent/phase/result/terminal/comparison pins. It reruns verification without launching a worker and checks comparisons against existing expected values without rewriting result/comparison/ack artifacts. Old, changed or partial receipts fail. A future authorized retry would require a new explicitly versioned attempt protocol, not overwriting this ownership directory.

The inherited controller uses a new session/process group, closes owned pipe descriptors and on handled post-Popen exception/interruption terminates only its child group, escalates after5seconds, reaps and attempts terminal publication. Actual worker requires anonymous inherited pipe/hash/nonce/live controller PID/start-time before scientific imports, repeats review/source/parent/resource admission, sets parent-death SIGKILL and hard resource limits plus default wall alarm. Direct handmade-file/CLI entry rejects. These are accidental-entry/cleanup defenses, not a same-user security sandbox or power-loss guarantee.

Per stage: nice15, one specifically allowed CPU, numerical threads1, float64, cxx disabled, NUMBA fastmath=False; wall600seconds, CPU soft540/hard550, RSS4GiB sampled watchdog, address space8GiB hard, file64MiB hard, stage/cache512MiB sampled watchdog and no cores. A fresh receipt within300seconds must find no conflict with actual CPU/memory/shared staging/owner commitments and pin protected PID/start times; >=6GiB available memory and>=2GiB free disk are necessary floors, not permission to overlap national2018/2022 or other owner jobs. Resource use of this new symbolic/NUMBA graph remains untested. No automatic retry or cap widening occurs.
