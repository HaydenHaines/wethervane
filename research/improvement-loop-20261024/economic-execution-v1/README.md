This package prepares a retrospective **aggregate F-only comparison**. It cannot qualify or promote the selected Senate count stack. No MCMC has been launched by its implementation or tests. Root must separately review the frozen execution plan before invoking `--run`; the runtime acceptance is only a runtime review.

The immutable preparation is `../economic-experiment-v1/prepared-v1/plan.json`, SHA `cfe669f6cef8cec82702b03e9ced060edf022fd434df131483515a054d24aef9`. Its README documents the actual Senate training panel, midnight H14 CPI vintage restrictions, prior convention, party orientation, macro collinearity and 2022 extrapolation. This runner preserves those inputs and owner laws. The owner inspection in the integration audit is dated v19; subsequent count-stack preparation is a separate owner workflow.

The sixteen jobs are H0, F0, E01 and E01_sd025 at each of 2018/2020/2022/2024. H0 is the unchanged refreshed-history recipe; F0 is the unchanged relative-context recipe. E01 jointly fits F0 plus one earlier-cycle-standardized president-oriented headline CPI mean term with Normal(0,.05) coefficient; E01_sd025 changes only that SD to .025. The tighter prior is a predeclared sensitivity and cannot be selected by scores. Each job uses four sequential independent chains, 1500 warmup and 4000 retained draws per chain, target acceptance .97, maximum tree depth10, and explicit per-chain seeds in the plan. All arms retain the same data and computational budget. The additional predictor, all existing coefficients, cycle effects and cycle/race scales are inferred jointly.

For every retained joint posterior row, five genuine future replicates use that row's complete coefficient/scales vector, one new Normal cycle shock shared by all target races, and independent Student-t5 race residuals. No columns are spliced across fits or posterior rows. Saved NPZ files include shares, logits, new cycle/race standardized shocks, and original posterior-draw/replicate mappings. Replicates remain contiguous in their original chain order. Parameter diagnostics require rank Rhat<=1.01, bulk/tail ESS>=400, zero divergences and zero depth10 hits. Predictive nonconstant coordinates require Rhat<=1.01 and bulk/tail ESS>=1000; winner probability MCSE<=.005 and target-subset seat-mean MCSE<=.03. Parameter ESS is evaluated on original posterior rows. Predictive ESS describes the simulated quantity, not extra fitted posterior draws.

The exact finite empirical share CRPS is primary. Secondary summaries are share WIS (central80/95 intervals and median), winner Brier/log score (probability floor1e-6), interval coverage/width, expected/median margin and narrow/large-margin probabilities. The pointwise winner rule is share>.5; ordinary target truths must be interior and non-tied. Shares and truths are checked for bounds and finiteness. The forecast-time F0 winner probabilities freeze common competitive [.1,.9] and near-even [.4,.6] masks for every arm. Empty masks remain unavailable. Races receive equal weight within each cycle; cycles receive equal weight within A=(2018,2022), B=(2020,2024). Always-half winner scores and the equal-earlier-cycle D-win-frequency reference are reported separately.

Numerical score errors use the unchanged owner influence and chain/batch routine, with contiguous batches of 250/500 future draws corresponding to 50/100 original posterior rows, plus between-chain variance. CRPS influence is centered for variance computation; its raw mean is not the CRPS. Independent arm differences use the square root of the sum of arm numerical variances; equal-cycle tier errors combine independently seeded cycle numerical variances before averaging. These are Monte Carlo errors, not uncertainty from having two elections per tier or many correlated races. Constant winner indicators and zero empirical true-outcome tails are explicitly unresolved: zero delta MCSE does not certify rare tails, and corresponding winner-score two-MCSE flags are unavailable. Every per-cycle, competitive-mask and B-tier loss remains visible. The absolute .0005/relative2% CRPS thresholds are review aids, not adoption rules.

Execution proceeds chronologically. A fold compiles only earlier numeric labels; all four prediction files and seals, then the common F0 masks, must exist and have matching hashes before its target-label numeric parser runs. Target rows are selected using cycle metadata before numeric conversion. Target labels never enter features/scalers or fits. Earlier evaluation outcomes can enter later folds' training. This is a declared retrospective comparison, not an untouched global holdout or a prospective forecast.

Every attempt uses a new exclusive directory. Each complete raw chain is saved immediately with warmup, named chain identity, seed and byte pin. Each transition is also flushed to a journal, preserving partial chain points/stats if sampling fails. Raw banks, predictive/fit diagnostics, negative terminal receipts and failed attempts remain present; no failed fit automatically retries or promotes. A continuation requires a separately generated, externally SHA-pinned manifest binding the prior launch, complete-chain receipts and every job terminal (including explicit absence). Reusing a chain verifies the receipt again, its raw bytes, job/seed/chain identity, retained count and warmup count. The new attempt references the old complete bank; it never overwrites it. Terminal presence and bytes are checked before creating a continuation and again at job reuse; deleting or changing a negative terminal rejects. A preserved numerical failure cannot silently be retried. A continuation can reproduce already scored folds with unchanged settings, so it does not restore unopened-label status.

Root owns `runtime/`. The runner authenticates the externally expected runtime-acceptance SHA and every inner result/checker/review/lock pin, exact locked package versions, Python invocation path and virtual-environment prefix before execution imports. The runtime review discloses the PyMC/SciPy density normalizer offset (about7.4e-7 joint, below5e-9 per factor), matching transformed gradients and invariant offsets at supplied points. No law or convergence gate was changed to accommodate that discrepancy. Execution plan validation pins all scientific imports, own code/tests, frozen preparation inputs and source snapshots. This verifies declared bytes, not original data admission or original BLS posting authenticity.

`runner.py --prepare <new-directory-in-this-package>` snapshots and emits a reviewable execution plan without sampling. `--plan <plan.json> --plan-sha256 <external-SHA>` validates it without sampling. Root's eventual reviewed launch additionally supplies `--run <new-attempt-directory> --runtime-certificate runtime/acceptance.json --runtime-certificate-sha256 <external-SHA>` with the same four thread variables. Recovery preparation uses `--seal-continuation <prior-attempt> --continuation-output <new-manifest.json>`; this only creates a review artifact. A subsequent reviewed new attempt uses `--continuation-manifest <manifest.json> --continuation-manifest-sha256 <external-SHA>`.
