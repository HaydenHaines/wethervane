# Parent reuse needs a new parameterized kernel, not a mutable existing callable

The existing frozen TX NUMBA callable cannot simply be switched to another protected parent. Its event×24-cell exposure enters as a NumPy array and becomes a TensorConstant in the graph. `ProtectedPopulation.exposure` reads `c.protected['exposure']` at components.py:56. The compiler requires this output to remain an exactly equal NumPy array before tensor conversion (graph.py:452–460). Its API has no symbolic-parent argument or mutable parent-data channel. A provider emitting a symbolic exposure tensor is explicitly rejected.

Source inspection finds exposure is the only direct numerical parent read in the selected incumbent component implementations. It enters cell intensity as exposure×community×propensity, then category rates and the observed-event Gamma frailty coordinate density/Jacobian. The standardized observed-total centers/scales depend on observed counts and configuration, not parent values. The frozen successor also validates the entire selected parent as a gate, but introduces no further parent-dependent numerical input. Its poll mixture depends on count rates downstream from exposure. The fixed demographic reference is Problem data, not a parent-specific reference to update.

The eight saved parents share shape (3,24), event/cell axes, Problem/upstream identity and original mass 0.125. Exposure, row ID and parent ID vary. Parent identity hashes the complete canonical parent record, including its mass. IDs, lineage and mass additionally enter compiler contracts and the scientific target ID; `parent_mass_used_in_logp=false`. Therefore sharing a numerical kernel must retain separate authenticated parent/target envelopes. It cannot turn eight conditional targets into one pooled posterior, reuse the first parent's target label, or multiply the conditional likelihood by parent mass.

# Executed tiny evidence

`probe.py` constructs only an invented two-event/three-cell, six-coordinate model. It includes an observed-total Gamma frailty coordinate density with its log-G and scale Jacobians, a transformed LogNormal parameter, Normal priors and Poisson observations. No actual TX graph is imported or built.

Before optimization, strict identity-based `graph_replace` replaces the exact exposure port in both logp and gradient by an explicitly shaped, positive finite symbolic input. One NUMBA function then evaluates A→B→A. Each result agrees with an independently rebuilt fixed-parent FAST_COMPILE model: maximum density error 1.78e-15 and maximum gradient error 4.44e-16. The two parents give different densities, and returning to A restores its result. Wrong shape, negative exposure and nonfinite input reject. Conditioning masses remain external and unchanged; this is not evidence of conditional normalization.

The original native compiler exposure-guard AST is also executed unmodified on tiny values. It accepts the original array and rejects both a different-parent array and a symbolic input. This directly confirms the native API boundary without running its full compiler. The first tiny harness assumed SpecifyShape had an owner node; constant folding had already yielded a TensorConstant. That failed harness is preserved in `first-probe-failure.log`; the corrected test targets the exact exposed port object without matching constants by value.

This demonstrates a viable **generic numerical implementation technique**, not completed reuse of the actual frozen TX kernel. The actual logp/dlogp may clone or rewrite the exposure node; exact identity survival there has not been checked in this packet. An already optimized/compiled constant graph cannot safely be retrofitted by changing array bytes or matching constants by numerical equality.
