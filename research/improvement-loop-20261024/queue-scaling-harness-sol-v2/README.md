## Controller linkage and remaining trust

The inherited socket is a local controller/worker rendezvous bound to current process birth and pinned records. Request, admission, leaf admission and before-operation resource receipt are independently fingerprinted. Grants expire after2 s. Before-operation sample age is bounded; the controller records admission freshness and batch timing. A failed birth registration never delivers a grant, so the trusted worker cannot begin queue work merely because Popen succeeded. Direct CLI --worker without the linked descriptor fails closed.

This is **not anti-forgery against arbitrary same-user Python**. A malicious owner could create its own controller/socket, rewrite the local evidence or run other code. Parent death after grant, SIGKILL, filesystem/proc stalls and host failure are not fully solved. The resource gate is a fresh sampled observation, not an atomic proof no owner starts one microsecond later. Actual queue import remains after group join; bootstrap/read-only preflight is outside leaf counters and must not be mislabeled as complete in-leaf CPU cost.

Read-only worker checks precede cgroup mutation; they do not create an exclusive kernel lease against arbitrary external migration or subgroup creation. PIDfd-only teardown avoids recursively harming an unknown subtree even if topology changes between observations. If a known process migrates after a check, its birth identity remains the ownership anchor; if unproven, it is not signaled. Coherent receipt forgery, escaped unrecorded jobs and hostile namespace manipulation remain outside the cooperating-client assumption. Missing/unreadable identities, unexpected groups, unresolved waits or still-live recorded fixtures give cleanup_uncertain. There is no guarantee every uncertain process is forcibly gone; retained handles/evidence are the recovery boundary.

The real path still constructs genuine tiny native-receipt histories through the unmodified source: cumulative1/2/4/8, capacity1, at most16 launch intents, no-fork1KiB fixture, nice15, 2 s executor timeout, source-bound queue receipts and no scientific-cycle/forecast claim. Old source packets are never output directories. New output uses exclusive fresh scratch receipts.

Requested5 s/120 s operation/batch checks are not hard real-time bounds on blocking I/O, proc or scheduling. RSS/PSS are samples, aggregate cgroup memory is resource charging, and only in-domain processes are included by those kernel counters. An external caller must preserve process errors when durable terminal publication itself fails. No actual real resource trace, cleanup, worker handshake, controller crash or queue scaling performance has been validated.

V2 no longer needs writable cgroup.kill. It still requires a genuinely fresh empty canonical delegated leaf, finite CPU/memory/pid limits, readable accounting and writable cgroup.procs. Full I/O accounting is not silently dropped. The prior read-only environment observation found cpu/memory/pids delegation but no io.stat under the observed user service. That historical observation is **not a fresh V2 admission**, and no suitable leaf was created or tested here. Actual pilot remains unadmitted pending independent review and a fresh eligible leaf/owner/resource handoff.
