# November CPS Voting weights and person-key evidence (2018/2020)

Research note, retrieved 2026-10-26 from official Census Bureau pages and technical documentation. No microdata were downloaded and no model was fit.

## Conclusion

For both the November 2018 and November 2020 CPS Voting and Registration Supplement, Census's year-specific technical documentation explicitly says there is no supplement-specific point weight and directs users to the basic CPS person weight `PWSSWGT` (positions 613–622) to tally supplement items. The same November person file contains the CPS basic items and Voting supplement fields, so use of that prescribed point weight with the Voting answers does not require a separate-file person join.

Both year-specific record layouts document `QSTNUM` as a unique household identifier and `OCCURNUM` as a unique person identifier, each valid within a specific month. This supports a within-month person key; it does not by itself validate a join to replicate weights.

I found no year-specific November Voting replicate-weight file or Voting-specific replicate-file merge specification in the official 2018 or 2020 supplement directory listings reviewed. This is a bounded negative finding about the checked listings, not proof that no such file exists elsewhere. The official documentation's statement “no supplement weight” concerns the supplement point weight and does not expressly rule out a separate replicate-weight file. The generic person-supplement replicate memo in the 2018 directory is not enough to bridge this gap: it is not year/Voting-specific and its described weight naming family differs from `PWSSWGT`.

The official 2022 and 2024 directories contain explicitly named November Voting replicate-weight SAS layouts. The 2024 layout specifies `QSTNUM` + `OCCURNUM` followed by `REPWT0`–`REPWT160`. These later-year materials establish that Census has published year-specific Voting replicate layouts in later years; they cannot establish 2018/2020 file availability, layout, variance procedure, or historical release vintage.

## Sources and precise evidence

1. [2018 Voting and Registration technical documentation](https://www2.census.gov/programs-surveys/cps/techdocs/cpsnov18.pdf), attachment 3, PDF pp. 9–10 (printed pp. 3-1–3-2): supplement is part of November CPS; lines on p. 10 say there is no supplement weight and prescribe `PWSSWGT` for supplement tallies. Attachment 7, PDF p. 101 (printed p. 6-81), documents `QSTNUM` and `OCCURNUM` as monthly unique household/person identifiers. Attachment 7, PDF p. 95 (printed p. 6-75) defines `PWSSWGT` as final weight, used for most tabulations, with four implied decimals and edited universe `PRPERTYP=1–3`.
2. [2020 Voting and Registration technical documentation](https://www2.census.gov/programs-surveys/cps/techdocs/cpsnov20.pdf), attachment 3, PDF pp. 9–10 (printed pp. 3-1–3-2): same no-supplement-weight statement and instruction to use `PWSSWGT`; the November CPS computer file carries the supplement. Attachment 7, PDF p. 101 (printed p. 6-81), documents the same month-limited household/person key. Attachment 7, PDF p. 95 (printed p. 6-75), defines `PWSSWGT` as the final weight.
3. [Official 2018 supplement directory](https://www2.census.gov/programs-surveys/cps/datasets/2018/supp/), listing lines 48–53: includes `nov18pub.dat.gz` and `.zip`; nearby entries include `oct18rep`, not an explicitly named November Voting replicate file. The listing also contains generic replicate-weight instructions; these are not a Voting-specific 2018 replicate layout.
4. [Official 2020 supplement directory](https://www2.census.gov/programs-surveys/cps/datasets/2020/supp/), listing lines 46–53: includes `nov20pub.csv`, `.dat.gz`, and `.zip`; nearby explicit replicate entries are for other months/supplements (e.g. October), not an explicitly named November Voting replicate file.
5. [Official 2024 November Voting replicate SAS layout](https://www2.census.gov/programs-surveys/cps/datasets/2024/supp/cps_voting_repwgt_nov24.sas), lines 0–10 and 24–38: says it documents the November 2024 Voting ASCII replicate file `nov24rep.dat`; parses `QSTNUM`/`OCCURNUM` then `REPWT0` onward. Used only as a contrast, not evidence about 2018/2020.
6. Related prior research: `../cps-replicate-followup-sol-v1/README.md` and `sources.json` document a generic 2012 person-supplement replicate memo. Its `QSTNUM`/`OCCURNUM` merge recipe and `PERSUPWGT0` equality check are generic; its described `PWSUPWGT`/`SRWGT`/`NRWGT` naming does not establish applicability to November Voting's `PWSSWGT` or establish year-specific 2018/2020 replicate files. Do not treat this memo as validation of the target join.

## What is still needed to close the replicate question

A year-specific official 2018/2020 November Voting replicate file (or authoritative documentation of its location and release) plus its record layout and variance instructions. The evidence should explicitly establish that its person rows join one-to-one to the corresponding November Voting person rows on the within-month key, identify the appropriate full-sample weight and replicate family, and state the correct variance formula. Directory listings and the generic memo do not establish those facts. Historical first-public-release timing would require separate dated release evidence; directory “last modified” values alone are not first-release proof.
