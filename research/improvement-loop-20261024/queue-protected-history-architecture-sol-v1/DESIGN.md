# Proposed protected-history authority for an incremental improvement loop

SOURCE-ONLY DESIGN, not implementation, resource receipt, service deployment or production adoption. No jobs/tests were run for this packet. Sources are pinned in source-pins.json. Existing V2/full-audit/frontier/memo packets remain unchanged. This design changes the authority/storage contract in a NEW opt-in domain; it cannot honestly claim identical immediate arbitrary mutable-history tamper detection while avoiding visits to those bytes.

## Why the current boundary prevents the desired shortcut

queue-v2-incremental-assessment-sol-v1 measures real history scans and source authentication, and explicitly returns trusted_mutable_index_no_historical_audit for its separate derivative. SQLite atomic admission protects cooperating transition correctness, not arbitrary owner rewrite or rollback. queue-durable-frontier-sol-v1 removes historical scans from selected ready/active SQL, but its own findings distinguish synthetic query-plan measurements from authenticated actual histories and retain mutable-index/audit limits. Neither creates protected scientific authority.

Current ancestor execution.ownership_audit authenticates all intent/claim/prepared/source/effective-spec state and refreshes every historical live input/executable; registered() includes job-lock device/inode. Four source-backed tiny real-history counterexamples already show: a same-size/mtime input edit changes drift with identical ownership evidence; a same-byte job-lock inode replacement rejects; namespace corruption rejects; cooperating dispatcher exclusion does not lock external inputs. A full result cache underD cannot preserve these checks. Pure decode memo still performs all these reads/hashes; it fixes no asymptotic rehash problem.

Three further storage counterexamples follow directly from these contracts:

* A same-UID file named bySHA or chmod0444 is still replaceable by its parent-directory owner; it can be chmodded/rewritten. Content addressing detects different bytes WHEN READ, not immutability or immediate unvisited-file availability.
* If SQLite, hash-chain history and latest-head file share a mutable/rollbackable domain, restoring an old consistent log+head+epoch validates internally. A locally self-authored digest/signature under a caller-accessible key does not supply an independent current floor.
* A valid signed old checkpoint can be replayed to a new client without a trusted monotonic floor or fresh authenticated authority query. Two neighboring files are not independent anchors. These are design counterexamples, not new destructive experiments or claims of actual tamper.

## Smallest architecture worth implementing next

Separate three roles:

1. Evidence authority owns immutable canonical admission/result/release records and content-addressed object storage. Only its narrow API can append validated events/advance head. Its database/storage/key are outside the mutable coordinator's write/rollback authority. A single online authority is simpler than an unreviewed distributed protocol.
2. Coordinator owns a rebuildable SQLite ready/active/blocked projection and disposable local file views. Neither projection digests nor local cached receipt paths are authority. It presents exact object/event IDs and an expected authority head/lease generation on every transition.
3. Executor retains the existing single-attempt/joblock/durable-launch/identity/cleanup semantics, consumes a selected versioned spec, and returns operational evidence. Scientific source/qualification decisions remain distinct; accepted_execution never means a qualified model.

Minimal authority implementation can use one protected SQLite transaction for canonical event bytes, unique logical job/output ownership, dependency references, active reservations and authoritative frontier updates. An append hash chain supplies ordering/integrity evidence; it does NOT alone make the store protected. The service's authenticated latest-head/read API is trusted. Offline compact membership proofs/Merkle trees are later optional work, not a promised property of this minimal version.

The independently retained checkpoint is(domainUUID,sequence,headHash,sourceRosterDigest,policyDigest,leaseGeneration). It lives in a distinct trusted authority/failure domain or is returned by a fresh authenticated authority request; caller retains exact acknowledged head/tool return outside the disposable coordinator. Requests carry fresh nonces/expected heads; responses bind nonce, commit ID, generation and status. New clients need a trusted bootstrap floor. If the authority itself is restored to an older backup, an independently durable monotonic floor/restore policy is required; ordinary signatures and a backup of the same database cannot solve it. No arbitrary whole-host/power-loss antirollback guarantee is asserted.

## Admission and release transactions

Admission: caller submits immutable canonical plan/spec/source/target/evidence descriptors plus explicit idempotency key and current head. Authority validates exact source/runtime/plan version and claims before commit. Input/source bytes claimed as immutable must be ingested and hashed into protected objects, not merely referenced by their current mutable path. Large existing object reuse is by an explicitly chosen protected object ID; do not skip validating a newly claimed live-path version because a digest filename exists. Scientific data eligibility remains unassessed unless a separate reviewed admission receipt exists.

Write/fsync/publish immutable objects first, then one SQLtransaction commits references, unique ownership, dependency/frontier updates, next sequence and newhead. A precommit crash leaves no accepted admission; durable unreferenced objects are orphans, not scientific success. Caller retains exact plan and retries by idempotency key. Postcommit response loss must resolve through authoritative lookup: identical bytes return the committed identity, changed bytes reject. No launch occurs without a committed reservation.

Release: after actual executor terminal/output/cleanup authentication, snapshot admitted outputs/effective binding/receipt chains into protected objects. Commit accepted/failure/blocked status, reservation release and descendant propagation/frontier changes in one authority transaction. Publication/fsync uncertainty isunknown, not success. If commit status is uncertain, retain capacity until authoritative idempotent lookup resolves it. Failed/blocked descendants remain explicit; no empty-frontier completion inference.

FS+DB atomicity is not assumed. Objects precede references; DB commit is authoritative only after its required durability semantics. Process death tests can check ordering/replay, not power-loss/storage-hardware guarantees. Protected object corruption/deletion is an availability/fault event detected on access/scrub; this contract must not advertise immediate verification of every unvisited historical byte.

## Dispatch/revalidation and complexity

At idle: authenticate current code/source policy (fixed code-size cost), fetch fresh authority head/fence and active/ready frontier, reconcile ONLY active processes/reservations with live identities/sessions/locks/cleanup. Selected job still validates its complete admitted spec, selected input/executable materialization and exact producer authority/result/terminal/output chain immediately before launch. New generation/head does not waive selected-source or live resource/owner admission. Authority unavailable/unknown head/unknown process -> stop new launches, retain evidence/capacity and report degraded state.

For immutable selected ancestors, obtain exact authority records/object IDs through the protected service and verify on read. Deduplicate shared ancestors per request; don't recursively revisit diamond paths. A selected job depending on all history still legitimately costs O(selected ancestry+bytes). Fixed active frontier can avoid O(all released history) work on each idle tick, but source hashing, selected object verification, B-tree/API costs and input sizes remain. No O(1) end-to-end or thousands-cycle throughput claim.

Mutable historical path files become caches/non-authoritative AFTER explicitly acknowledged protected archival commit. Edits to them may be detected on use or background scrub, not automatically every idle tick. This is the required visible contract change. If the user instead requires immediate live historical-path drift detection even for unused results, keep full scans or add infrastructure enforcement preventing mutation; no cache/index/hash tree can infer unread edits.

Current executor uses actual paths/inodes and local mutable claims. An adapter must bind protected logical object IDs to exact effective execution paths/versioned immutable input views and retain unique output claims/joblocks. A read-only source mount or separate-UID-owned namespace may be required for stronger protection. Without it, keep current per-selected-launch hashing and acknowledge the same post-check mutation race as the baseline. Do not equate an archive copy with original-path immutability or silently migrate existing stores.

## Concurrency, interruption and stale contexts

Authority reservation uses expected head/lease generation and transactional capacity/ownership checks, not a coordinator-local cached free slot. Lease expiry fences stale coordinator requests; it NEVER proves a worker dead, releases capacity or permits a duplicate attempt. Reconstruct active state from committed authority records, reconcile existing durable executor launch/joblock/identity evidence and require verified cleanup before releasing. Conflicting/unknown active state stays blocked; no automatic retry or kill of unrelated work.

Projection receipt records the exact authority sequence it represents. Crash before projection commit -> rebuild/replay from authority; crash after commit -> idempotent replay. Validate contiguous sequence/hash linkage and domain/source/policy version. A stale/corrupt/missing projection can be discarded/rebuilt after explicit validation; a corrupt/unknown authority head cannot be repaired by trusting that projection. Bootstrap may cost O(history) once and resumable authenticated checkpoints; normal idle operation must not repeat full bootstrap. Full independent audit/scrub remains an explicitly scheduled diagnostic, not an automatic trust substitute.

The decode prototype is synchronous-only; its complementary ContextVar review is pinned here (the primary regression review is separate). Copied/async contexts can retain its mutable memo after owner scope exit, repopulate it and cause nested-scope rejection; existing README excludes that usage, so its synchronous claim is not contradicted. Preserve it unchanged. A future service needs explicit active/generation invalidation checked on every use plus synchronization OR a strict single-context API. Authority requests/checkpoints must never inherit authorization from ContextVar presence or a stale local operation object. Durable epochs belong to the authority, not an in-memory parsing cache.

Continuous loop finality is per named closed finite batch with explicit nonempty admission count, all-terminal count and failed/blocked/accepted-unqualified breakdown. OPEN intake/no ready/active entries isidle, not complete work, no scientifically unnecessary-candidate inference and no global goal-complete signal. New admissions after a batch require new identities/epochs; qualification/promotion/publication stay separately governed.

## What can be researched locally versus infrastructure decisions

Authorized local next experiment: new throwaway domain, in-process/reference authority over temp CAS+SQLite, explicit trusted_mutable_same_uid_reference status, actual tiny commands, bounded crash/idempotency/epoch/frontier/revalidation tests. Fake service may simulate privilege denial/rollback to demonstrate contract rejection, but cannot claim OS-protected immutability, independently secured head or malicious same-user resistance. No production implementation or tests are included here.

Infrastructure/owner decision required before stronger claims or deployment: separate UID/service/key custody and write permissions; protected append/object semantics and durability/backup/restore floor; authenticated authority endpoint/bootstrap; immutable code/input view if selected; global concurrency/resource coordination and current owner lease integration. Changing ownership/mounts/chattr/kernel/cgroups/active jobs, creating remote services, publishing/pushing checkpoint roots or migrating production stores is outside this packet and is NOT executed. This is not a new user-approval request; it identifies decisions the authorized research reference cannot manufacture.
