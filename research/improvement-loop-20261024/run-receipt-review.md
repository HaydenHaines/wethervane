# Native run evidence adapter review

October 25, 2026 UTC. `run_receipts.py` connects actual owner evidence to the local append-only journal. It copies verified evidence; it does not run a model, advance a cycle, qualify a forecast, select an incumbent or publish a result.

Three bounded contracts are supported:

1. The Senate v16 zero-draw first-parent startup failure using the native share-coordinate execution plan, fixed attempt directory, failure/process/observer files and inventories. Its normalized numerical status is failed; no complete cut, precision or empirical claim is inferred. An optional owner checkpoint is a dated observation, not process-liveness evidence. Later native schemas and successful runs need separately reviewed adapters.
2. One cell of the exact reviewed House historical aggregate handoff. The implementation requires the trusted review digest, matching full declared fit plan, loaded plan source pins, fit/result identity and direct output hashes. The reviewed race diagnostics pass, but subtotal Monte Carlo precision fails. The normalized status preserves both. This is not a current election, candidate-count or chamber-control qualification. Transitive scientific ancestry is not replayed by the adapter.
3. The full-execution v2 current Texas attempt that completed sampling for its first population conditional and then failed convergence. The adapter binds terminal, plan, attempt paths, result, CSV diagnostics, archive and declared observation files. All eight original population masses remain intact; one sampled conditional is distinct from eight qualified conditionals. The pickle is preserved as opaque bytes. This is a failed fit, not a timeout, usable forecast or instruction to retry. The [independent review](completed-failure-adapter-review-sol-v1/REPORT.md) and [root acceptance](checkpoints/completed-failure-capture-root-acceptance-v1.json) record the supported scope.

## Independent review and repairs

Root and Luna challenged the original adapter; Sol repaired four concrete issues. Attachment now binds a canonical report and immutable verified pin tuple, rejects report mutation, checks fixed native attempt paths and observer inventories, verifies loaded House-plan source pins, and rejects conflicting hashes for one canonical path. Before writing any journal artifact, attachment stages and re-verifies all input bytes. A staged copy closes the verify/copy gap if a source changes during attachment. Content hashes establish byte identity, not source truth or authentication against a malicious caller fabricating an Inspection object.

The native Senate schema lacks an authenticated universal attempt manifest. Paths and native inventory relationships are checked, but byte-identical copied records without a stronger native identity cannot prove more than that contract. The trusted House review is deliberately fixed; arbitrary future review claims are rejected until their schema and trust boundary are reviewed.

Fourteen tests pass, including nine portable corruption/contract fixtures and five checks using actual checkouts or generic parsing. Missing owner checkouts are explicit skips in those integration checks; the current run had none. Together with the twelve journal and six mixture tests, [root's workflow run](evidence/workflow-tests-root-v2.log) passes 32 tests.

Both CLI attachments succeeded against the real local journal. Objects are retained by content hash under ignored `.improvement-ledger/objects`; large scientific arrays are not copied into Git. The normalized reports include the exact hashes and journal artifact identifiers. Attachment alone leaves the bootstrap cycle at its previous research revision; the later root checkpoint explicitly records the new synthesis separately.

No automatic runner, recovery daemon, scientific qualification gate, active-model registry or deployment integration exists in this adapter. Its concrete contribution is preserving genuine failed and reviewed owner evidence without turning either into a broader success claim.

The completed-failure extension passes 16 focused checks, including the exact native record and CLI attachment; the 14 existing adapter checks also pass with no skips. Independent counterexamples prompted four repairs: conflicting preservation errors, mismatched coordinates, an unrelated terminal directory, and omitted terminal diagnostics now reject. The adapter also copies the declared observation inventories. Attaching it left the journal's cycle phase unchanged. Native diagnostic extrema are checked against the CSV; draw-based diagnostics and transitive source ancestry are not recomputed.
