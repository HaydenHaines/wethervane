# Independent source review: actual symbolic exposure substitution attempt

## Finding

The failure packet's narrow statement is well supported: the script constructed the complete Jacobian-inclusive logp, successfully ran strict identity replacement of its exact exposure port and passed its input/removal/value-input assertions; it then aborted at the precondition that the same exact port be an ancestor of the already-derived `model.dlogp(jacobian=True)` expression. The exception occurred before strict gradient replacement was called.

This establishes only that the **exact original node object** was absent from the dlogp ancestry. It does not establish that dlogp was numerically independent of exposure, identify whether it retained an equivalent cloned/rewritten constant, or show the substituted logp's numerical values. The failure is symbolic construction evidence, not density or gradient parity.

## Source and execution evidence

I verified all 10 files pinned in `evidence.json`, the provider and selection pins, and all 62 actual dependency pins listed in `postmortem.json`; all byte sizes and SHA-256 digests matched. The provider's `selection()` authenticates every entry in `selection.json`'s source/input pin map before loading the original modules. Its `validate()` checks the complete problem identity, exact selected parent, six observation identities, parent masses, variance owner and target. The attempted script then builds only the original row-0 graph and checks parent identity, mass 0.125, population-cut target, `parent_mass_used_in_logp=False`, scientific target digest, and exact 3x24 exposure equality before constructing logp/dlogp.

The stage trace and Python control flow align: `construct_complete_original_jacobian_logp_and_dlogp` completed; `strict_replace_complete_logp` begins and contains the first expression's strict `graph_replace` followed by assertions that the explicit exposure input is present, the typed port is absent, and original value-variable inputs are preserved. Only after those statements does the loop append a success result and proceed to `strict_replace_complete_dlogp`. In that second iteration, `assert port in before` occurs outside the `try` block and is the failing line recorded in both logs. Therefore there is no per-logp exception path before advancing to dlogp. The packet accurately states that `result.json` and a serialized replaced graph were never written; its postmortem is a reconstruction from pinned source and trace.

The terminal shows a single bounded attempt, exit code 1 after 26.794 seconds, no watchdog termination, peak observed RSS about 593 MB, one observed thread and zero cache bytes. The launcher sets C++ off, float64, fastmath false, one-thread controls, fresh packet-local caches and resource limits. No linker function compile, numeric evaluation, sampler or forecast is recorded. I did not rerun any attempt or touch its cache.

## Challenge to the next proposal

Replacing the exposure port in the complete original `model.logp(jacobian=True)` and only then deriving a new gradient is the right structural next candidate: it avoids demanding that the typed port survive a gradient graph already constructed from the fixed-parent logp. This remains untested on the actual graph. The following details need to be explicit in any authorized next stage:

1. Preserve the **complete scalar logp with `jacobian=True`** before differentiation. PyMC `Model.dlogp()` first constructs `logp(jacobian=...)`, then applies `pymc.pytensorf.rewrite_pregrad(cost)`, then differentiates. A raw `pt.grad(replaced_logp, vars)` could omit PyMC's canonicalize/stabilize pre-gradient rewrite path. Pin and apply the same rewrite after replacement, or demonstrate full-vector parity with the native dlogp at the original parent.
2. Differentiate with respect to PyMC's same ordered continuous value-variable list as native `dlogp()` and preserve PyMC's flatten/concatenate convention. Verify every value-variable segment, the full vector length and coordinate names/order. The packet's phrase “original transformed value variables” is conceptually right but does not itself establish dlogp vector layout.
3. Treat `E` as a conditioning input, not a differentiated variable or new prior. After the derivative rewrite, assert the exposure input remains in the combined gradient graph wherever expected, all original value inputs remain, and no original exposure port or stale selected-parent constant remains in the substituted logp/gradient graphs. Fail closed if rewrites clone/fold away the intended binding.
4. Keep the native parent and first target contract immutable. The actual attempt validates/builds only row 0; it does not create another parent's graph or envelope. A future call with another exposure must authenticate that complete parent, its row/parent/upstream IDs, axes, mass and canonical target envelope. A gradient graph keyed to row 0's compiler contract cannot be relabeled as row 1's scientific target merely because exposure is an input.
5. Numerical parity remains a later gate. At least the original row-0 point should compare the replaced full logp and entire ordered gradient vector against the original fixed-parent implementation, with all Jacobians retained. Additional perturbed points and a second authenticated parent are needed before a generic kernel or reusable call path is claimed. No normalization or science qualification follows from symbolic graph construction.

## Verdict and limits

The source-pinned packet gives credible evidence that the exact-node substitution approach succeeds for actual complete logp and fails its exact-node precondition on the actual prederived dlogp. It does **not** show that no safe actual parent-conditioned gradient is possible. The gradient-after-logp proposal is structurally plausible but needs PyMC's pinned `rewrite_pregrad` and ordered flat-gradient semantics, strict post-rewrite graph/input checks, and eventually full numerical parity. No actual graph was reconstructed or compiled in this review.
