This is cooperative provenance checking, not impossible anti-forgery

The external caller/tool record is an explicitly trusted provenance boundary. A same-user adversary or deliberately dishonest caller can fabricate a complete stdout record, code, authorizations and coherent comparison/result files, then self-author hashes. Python source checks cannot distinguish that from trusted local execution without an independently controlled signing/logging authority. V2 does not claim to solve it. Schemas/hashes are not signatures; a newly self-authored digest proves no origin. The source-bound actual controller still owns graph calls and numerical receipts, and normal clients now must retain its actual successful response rather than using success-shaped marker files.
